# Git Workflow

Базовый и продвинутый набор Git-команд и инструментов для контроля версий. Учитывает безопасность и экономию времени.

## Основные команды (для ручного выполнения)

### Статус и история
```bash
git status
git log --oneline -10
git diff
Сохранение изменений
bash
git add .
git commit -m "feat: добавлен обработчик /start"
git commit -m "fix: исправлена ошибка подключения к БД"
Работа с удалённым репозиторием
bash
# Показать удалённые репозитории
git remote -v

# Скачать изменения (без слияния)
git fetch origin

# Скачать и слить с текущей веткой
git pull origin main

# Отправить изменения в удалённую ветку
git push origin main

# Отправить и установить upstream для новой ветки
git push -u origin feature/new-function
Откат изменений (локально и на удалённом)
bash
# Отменить незакоммиченные изменения
git checkout -- src/main.py

# Откатить последний локальный коммит (изменения сохраняются)
git reset --soft HEAD~1

# Откатить последний локальный коммит (полная потеря изменений)
git reset --hard HEAD~1

# Отменить уже отправленный коммит (безопасно)
git revert HEAD
git push origin main
Ветки
bash
git branch
git checkout -b feature/new-function
git branch -d feature/new-function
Плагины и инструменты для автоматизации
Для экономии времени и безопасности используй один из этих инструментов:

1. git-plugin-opencode (рекомендуется)
Устанавливается в OpenCode. Добавляет агентам безопасные Git-инструменты (commit, push, pull).

bash
opencode plugin install git-plugin-opencode
После установки агент сможет выполнять git push через встроенные инструменты, запрашивая подтверждение.

Безопасность при работе с удалённым репозиторием
Критические правила
Никогда не делай git push --force на общие ветки (main, develop) без крайней необходимости.

Перед каждым пушем проверяй, какие изменения будут отправлены: git status и git diff.

Если сомневаешься — создай ветку и пушь в неё, а потом делай Pull Request.

Как агент должен выполнять push
Агент обязан запросить подтверждение перед выполнением git push:

Сообщить, какие файлы будут отправлены.

Показать последний коммит.

Спросить: «Отправить изменения на сервер? (Да/Нет)».

Отправлять только после явного согласия пользователя.

Защита секретов
Никогда не коммить файлы с секретами (.env, config/secrets/). Добавь их в .gitignore.

Используй git-secrets для автоматической проверки перед коммитом:

bash
git secrets --install
git secrets --register-aws  # если используешь AWS
Пример рабочего процесса
Агент видит, что ты закончил фичу.

Он делает git add . и git commit -m "feat: ...".

Показывает лог последних изменений.

Спрашивает: «Всё готово для пуша? (Да/Нет)».

Если да — выполняет git push origin <текущая_ветка>.

Если нет — ждёт дополнительных правок.
